- **Charts now draw in the Mac TUI and on the iPhone.** A `chart` tool call renders its chart in the conversation's own place — the braille plot, the ⅛-cell bars, the stacked rows, the 100 % pie bar and the sparkline rows (one per series at 40–59 columns; the data table below 40), centred to the transcript width — instead of a generic `● Chart …` tool row and its one-line result: the chart is part of the reply, not a tool block (it keeps no bullet, no connector, and is exempt from the generic body cut). It is drawn from the call's own arguments, re-validated by the client with the same caps as the daemon, so a resumed session shows the same chart and a forged or unreadable spec falls back to the plain tool row rather than crashing. Ctrl+O — or a click on the chart's caption — expands it to 16 plot rows with per-series min/max/last and the data table. A new `tui.chartGlyphs` setting (`braille`, the default, or `blocks`) draws quadrant blocks for a font that has no braille patterns, which a terminal cannot report on its own. On the iPhone the same call draws a vector chart (`react-native-svg`, so the app needs a new dev build) full width on the conversation background, with no card and no tool chrome: the title, a monospace hero number with its change pill, then smooth monotone lines with a soft gradient, rounded bars and a gapped donut in the shared palette, in light and dark. It too is drawn from the re-validated arguments, live and after a reload, and VoiceOver reads it as one element whose label is the chart's summary; a failed, refused or invalid call keeps the plain tool row.
