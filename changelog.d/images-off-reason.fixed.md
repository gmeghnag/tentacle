- **An image the session cannot take now says which of the two causes it is, instead of always telling you to update.** Pasting an image path into a session whose model has no vision on the current build said `this daemon does not take images (its model has no vision, or it predates images — update it)` — two unrelated causes merged into one sentence, advising an update of software that was already up to date and never naming the setting that would fix it. The client holds the facts to tell them apart: `initialize` enforces protocol equality, so a daemon that handshook at the version that introduced images and advertises no image input simply has a model whose config is off. So a current daemon now says `<model> is configured without images — set model.images true in your config if this model takes images (tentacle config set model.images true)`, naming the model it reports (or this laptop's own for a worker/pod daemon) and the exact key and command; a model name from the wire is stripped of control characters and bounded before it reaches a terminal. Only a daemon that really predates images — an older protocol, or one that answers `attachment/put` with `MethodNotFound` — says `this daemon predates images — update it`, from one shared constant. An unreadable model name invents nothing, and a handshake that has not answered yet is never treated as evidence of age.
