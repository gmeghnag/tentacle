## Implementation

*— claude-sonnet-5-5, 2026-11-26*

### Load-bearing assumption
The compact row `[styles.body, styles.row]` inherits `flexWrap: "wrap"` from `body` (`Composer.tsx` styles); `row` does not cancel it. The red run showed the button below the field. `nowrap` ALONE made it worse (button gone, off the right edge: the input kept its open-shape width), so the real cause is the input keeping `width: 100%` after blur; wrapping only decided where the overflow went.

### Design
1. `styles.row` gets `flexWrap: "nowrap"` AND `inputCompact` re-sets every property `inputOpen` sets (`flexBasis: 0, width: "auto", minWidth: 0, marginRight: 0`) instead of relying on dropped props (the resting row is one line by contract). The open shape is untouched. The «Send now» pill lives in the same row and gets the same fix.
2. Pure `jumpBottom({mode, position, bounds})` in `floating-button.ts`: when the hub rests at the CENTRE and its column overlaps the pill's row, the pill's `bottom` becomes the hub's top + `BAND_MARGIN`; otherwise 12 as before. `SessionScreen` only feeds it to `styles.jump`. Product choice (stated): the pill lifts above the hub rather than the hub avoiding it, because the hub floats and nothing behind it may move (owner rule for feat/mobile-hub-center).
3. The app is right, the flow is stale: flow 33 now asserts `hub-label` text «Nothing running» (and no activity sheet). No `hub-notice` dependency.
4. `deleteQuestion` returns `{lead, file, tail}`; `WorkflowStart` renders the file in `MONO`. Flow 46 asserts the question text has no backtick.

### Files
`apps/mobile/src/ui/Composer.tsx`, `src/floating-button.ts`, `src/screens/SessionScreen.tsx`, `src/workflow-landing.ts`, `src/screens/WorkflowStart.tsx`; tests `test/floating-button.test.ts`, `test/workflow-landing.test.ts`; flows `23-composer-keyboard`, `33-hub`, `46-workflow-landing`.

### Failure modes
Hub at an edge / header mode / no band / hub in the upper half: pill unchanged (unit-tested). Open composer shape: unchanged.

### Tests
