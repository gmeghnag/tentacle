## Implementation

*— claude-opus-5-5, 2026-10-24*

### Load-bearing assumption

**A `session/update` the daemon emits while the session is idle (outside any
turn) reaches every attached client at once, and a client that attaches later
gets it only until the next cut — after that ONLY the snapshot can tell it.**
So the title must travel two ways: a broadcast update for the attached
clients, and a field of the snapshot (and of `session/list`) for everyone
else. Proof:

- `emit` numbers, buffers and fans out to every attachment synchronously
  (`hosted-session.ts:743-754`); `background_exit` already uses it while idle
  (`:339-347`).
- `attach` without a covered `since` replays from the current cut
  (`:629-652`); `recordCut` evicts the ring up to the cut (`:725-733`), and
  every `finishTurn` moves the cut (`:1096`).
- Repro above: A gets the idle update live; B (late, resync) gets it replayed;
  C (after the next turn) gets nothing.

Secondary (proved the same way): an older build's store parser rejects an
object `title` with `"title" is not a string` and accepts a string one
(`agent/src/session-store.ts:217-221`; Repro) — the lever that makes
downgrades loud (see Persistence).

### Preconditions

- **Unknown method → `MethodNotFound`** before any handler (`transport/src/peer.ts:334`);
  the daemon's `Connection` dispatches by `Method` (`daemon/src/connection.ts:162-189`).
  An older daemon answers `session/rename` with `MethodNotFound`.
- **Payloads are strip schemas**: an unknown field is dropped on parse (AGENTS §7
  forward compat; `protocol/src/session.ts:241-251` `SnapshotResultSchema`,
  `:275-287` `OpenParamsSchema` are plain `z.object`).
- **Display class**: a client skips an unknown display update, reporting it
  once per type per session (`client/src/mapping.ts:49-69`,
  `client/src/session-reducer.ts:221-226`); an idle one is kept for the next
  turn's notices (`client/src/remote-session.ts:396-401`).
  `UPDATE_CLASS` is a `Record`, so a new type without a class does not compile
  (`protocol/src/updates.ts:171-192`).
- **Not-turn-scoped updates are routed in `RemoteClient`** to dedicated
  listeners even while idle (`background_exit`, `client/src/remote-client.ts:1144-1150`);
  `RemoteSession` ignores them inside a turn (`remote-session.ts:521-529`).
- **Steering window**: no `await` between the agent's last drain and
  `finishTurn` clearing the controller (`hosted-session.ts:1000-1007`);
  `finishTurn` is synchronous and only *captures* for the persister (`:1093-1103`).
- **Model on the laptop**: a pod daemon's agent gets `ProxyModelProvider`
  (`cli/src/serve.ts:246-266`); the laptop serves `model/stream*` with its LOCAL
  provider, passing the pod's `ChatRequest` (incl. `maxTokens`) through
  (`client/src/remote-client.ts:1311-1320`; `daemon/src/proxy-model.ts:72-73`);
  an abort crosses the tunnel (`proxy-model.ts:187-228`). Per-type model ids on
  the same endpoint already exist (`cli/src/wiring.ts:270`, `configuredModelProvider(config, modelId)`,
  `cli/src/model-provider.ts:13-29`); over the tunnel the override is used for
  every type (same line).
- **Persistence**: only `serve` persists daemon-side (`session-host.ts:62-66`,
  `:302-304`); a record the daemon cannot read is blocked and never overwritten
  (`cli/src/serve.ts:135-152`); `parseDaemonRecord` refuses an unknown
  `schemaVersion` (`persisted-session.ts:155-160`). The laptop parser keeps
  extra top-level keys as-is (`session-store.ts:201-204`) — so a NEW key would
  be half-loaded by an older build (kept in memory, dropped at its next save);
  only a type change of a checked key (`title`, `:217-221`) is rejected.
- **`updatedAt` = last conversation change only** (task 1, owner-approved;
  `hosted-session.ts:270-276`, `session-persister.ts:84-90`).
- **Session ids/titles from a pod are bounded + control-free on the client**
  (`protocol/src/text-line.ts:11`, `line(max)`), sanitised daemon-side by
  `wireLine` (`daemon/src/mapping.ts:63-66`).

### Design

#### The title, one truth: `TitleState` (pure module `daemon/src/session-title.ts`)

```ts
export type TitleSource = "auto" | "model" | "user";
/** absent/"auto": derived from the history (`sessionTitle`) — the daemon's fallback. */
export type TitleState = { readonly source: "auto" } | { readonly source: "model" | "user"; readonly text: string };
```

Pure, React-free, unit-tested (AGENTS §7 "logic in pure modules"):

- `titleText(state, messages)` → `state.text`, or `sessionTitle(messages)` for auto.
- `titleInput(messages)` → `{ firstUser, firstReply } | null`: the first
  `user` message and the first non-empty `assistant` content after it, each
  cut to `TITLE_INPUT_CHARS = 2000`. `null` → no exchange yet.
- `shouldGenerate({ state, messages, failures, inFlight, closed })` → true iff
  `source === "auto"`, `titleInput(messages) !== null`, `!inFlight`, `!closed`,
  `failures < TITLE_MAX_FAILURES (2)`.
- `titleRequest(input)` → the `ChatRequest`: a fixed system prompt ("Reply with
  ONLY a 3–6 word title for this conversation, in the language of the user's
  message. No quotes, no trailing punctuation."), one user message carrying
  both texts, `maxTokens: TITLE_MAX_TOKENS (256 — room for a reasoning model's
  thinking)`, no tools.
- `cleanTitle(raw)` → `string | null`: first non-empty line of the TEXT events
  only (reasoning ignored), surrounding quotes/backticks and a trailing `.`
  stripped, `wireLine(…, TITLE_MAX = 80)`; empty → `null` (= failure). Daemon-side
  text processing of the model's own output — not a client guessing daemon state.
- `applyGenerated(state, text)` → `{ source: "model", text }` iff
  `state.source === "auto"`, else `state` unchanged. **A model title never
  replaces a model or user title.**
- `applyRename(state, text)` → `{ source: "user", text }` (always wins).
- `encodeTitle(state, messages)` / `decodeTitle(value)` — the record form (below).

#### When generation fires — never blocks or delays a turn

- **Moment:** at a turn's end (`finishTurn`, `hosted-session.ts:1079-1104`),
  after `persist()` and `settleSuccessor()`, call `this.kickTitle()`. It does
  **no work in the steering window**: it only schedules `setTimeout(…, 0)`.
  The macrotask re-checks `shouldGenerate` (and `!this.running`: a successor
  or a new prompt may have taken the slot) and then starts `generateTitle()`
  (fire-and-forget, never awaited by anything, never throws out).
  "After the first exchange" = the first turn end at which `titleInput` is
  non-null (any stop reason: a cancelled first turn with no reply does not
  qualify; the next one does).
- **Never delays the user:** any operation that takes the busy slot —
  `prompt` (`:786-790`), the send-now successor's start (`startSuccessor`,
  `:910`), `compact` (`:1151-1153`) — first aborts an in-flight title job
  (`this.titleJob?.abort()`, synchronous). On a single-slot local server
  (llama.cpp) a title request therefore never queues ahead of the user's
  turn. An attempt aborted this way is not a failure; the next qualifying
  turn end retries. `close()` aborts it too.
- **Timeout:** `TITLE_TIMEOUT_MS = 30_000` (local models are slow), via
  `AbortSignal.any([job, AbortSignal.timeout(…)])`.
- **Cost / size:** one call per session in the normal case; at most
  `TITLE_MAX_FAILURES = 2` failed attempts per incarnation (memory; a restart
  resets it — bounded by restarts). Input ≤ 2 × 2000 chars + a short system
  prompt; output ≤ 256 tokens.
- **Error / timeout / empty / cancel:** the state stays `auto` (the truncated
  first message — decision 17's "never untitled"), nothing is broadcast, the
  failure is logged through the session's existing error sink
  (`TurnErrorPolicy.onTurnError`, `hosted-session.ts:170-179`) as
  `title generation failed: <message>` — daemon log only, never the user's
  terminal (AGENTS §7 "never write raw…"). No client ever invents a title.

#### Which model — and "model stays on the laptop"

- `AgentFactory`'s result (`session-host.ts:41-46`) gains optional
  `titleModel?: ModelProvider`; `HostedSession` receives it (absent → no
  generation, `auto` forever; tests and any factory that omits it).
- `buildAgent` (`cli/src/wiring.ts`, the return at `:294`) returns
  `titleModel = options.modelOverride ?? configuredModelProvider(config, config.titleModel ?? config.model)`
  — the exact pattern of the sub-agents' `modelFor` (`:270`).
- **Pod daemons** (`serve --stdio` with `modelProxy`): `modelOverride` is the
  `ProxyModelProvider`, so the title request goes over `model/streamChunked`
  to the laptop, which runs it with its LOCAL provider — endpoint and key
  never leave the laptop. No new laptop capability: it is the same method the
  pod's agent already calls for every turn. The pod's `titleModel` config is
  ignored there (the wire request has no model id); the laptop's main model
  answers (Notes/debt).
- **Config:** new optional `model.titleModel` (a model id on the same
  endpoint, `config/src/schema.ts:10-37`, resolved into `TentacleConfig`).
  Decision 17's "optionally a cheaper model of the same provider, if
  configured". Unset → the main model.
- The title call does **not** fire `model_request` hooks: they are the agent
  loop's per-round notification (`docs/feat/hooks-turn.md:21`); documented in
  that doc (Q3).

#### Rename — `session/rename`

- **Request** `session/rename { sessionId, title: string }` → result
  `{ title: SessionTitle }` (the stored, sanitised value). The daemon applies
  `wireLine(title, TITLE_MAX)`; empty after sanitising → `InvalidParams`
  ("a title needs at least one visible character"). Param schema bounds the
  raw string (`z.string().min(1).max(MAX_SESSION_TITLE * 4)`) so a hostile
  client cannot send megabytes.
- **Live** id → `applyRename`, abort an in-flight title job, `persist()`,
  broadcast `session_title{source:"user"}`. Allowed during a turn (it does
  not touch the history or the slot: synchronous, no lock — AGENTS §7 "don't
  serialize the peer").
- **Not live** → `UnknownSession` on today's `main`. **If 2a has merged:** an
  archived id → rewrite its record's title through the persister (no reload;
  2a's named seam, `session-archive.md` "Seams for later tasks"); its
  `ArchivedEntry.title` updated in place.
- Idempotent by nature (a set). Any authenticated client may rename (one token
  = one principal, like `close`, `protocol/src/session.ts:296-310`; per-device
  auth is task 9).
- Does **not** move `lastChangeAt` / `updatedAt`: not a conversation change
  (task 1's approved ordering rule). A model title doesn't either.

#### Broadcast — `session_title` update, **display** class

```ts
SessionTitleUpdateSchema = z.object({
  type: z.literal("session_title"),
  title: line(MAX_SESSION_TITLE),
  source: z.enum(["model", "user"]),
});
```

- Emitted on every change of a non-auto title (generation success, rename),
  through `emit` — same fan-out, ring, seq as every update.
- **Class: `display`** (`UPDATE_CLASS`). Justification against AGENTS §7: no
  client must act on it for correctness — nothing hangs or desyncs if it is
  skipped (the turn/history state is untouched; the title is also in the
  snapshot and in `session/list`). An older client shows `unsupported` once
  per session and goes on. Not `mandatory` (that would fail an older client's
  turn over a label) and not `blocking` (the daemon waits on nobody).
- **Late attachers:** within the ring → replayed (Repro B); after a cut →
  `SnapshotResult.title` (first page, `{ text, source }`, source incl. `"auto"`)
  and `session/list`'s `title` (unchanged shape: `summary().title` becomes
  `titleText(state, messages)`). Snapshot title + replayed updates past its
  `since` converge on the latest value (each update is a full set; the last
  applied is the newest).
- **Auto changes are not broadcast** (from `"(empty)"` to the first message):
  every client already sees the prompt via `turn_start`.

#### Seed on recreate — `session/open { title? }`

- `OpenParams.title?: { text: line(MAX_SESSION_TITLE), source: "model" | "user" }`,
  honoured **only when the open creates the session** (exactly like `messages`,
  `session-host.ts:157-167`): a live id ignores it (the daemon's copy wins),
  as does an archived one after 2a.
- Why it is needed: pod `run`/`attach` and the in-process worker never persist
  (`session-host.ts:62-66`); `--resume` there always recreates from the
  laptop's copy (`local-runtime.ts:252-257`). Without the seed every resume
  would regenerate — and overwrite a user's rename, breaking "a user-chosen
  title is never overwritten".
- Trust direction: laptop → pod (the laptop's own data). A pod-supplied
  `source: "user"` in a snapshot only stops regeneration — display only,
  harmless (AGENTS §7: a pod can lie about what is shown, never act).

#### Persistence

**Record form (shared by daemon record and laptop store — one helper in
`@tentacle/agent`):** `SessionRecord.title: string | RecordTitle` where
`RecordTitle = { text: string; source: "model" | "user" }`.

- `auto` is written as today's **string** (`sessionTitle(messages)`) — an older
  build reads it fully; nothing is lost (auto is derivable from the messages).
- `model` / `user` are written as the **object** — an older build's parser
  rejects the file loudly (`"title" is not a string`, Repro): the `--resume`
  list reports it as skipped, `--resume <uid>` is fatal, an older `serve`
  blocks it and never overwrites it (`serve.ts:135-152`). **Never half-loaded.**
  (A new key like `titleSource` would be: the old parser keeps unknown keys,
  then its next save writes them away — `session-store.ts:201-204`.)
- `parseSessionRecord` accepts a string, or an object with a non-empty string
  `text` (≤ `MAX_SESSION_TITLE`) and `source ∈ {model, user}`; anything else →
  unreadable with the reason. Helpers `recordTitleText(record)` (display) and
  `recordTitleState(record)` (→ `TitleState`) replace every `record.title` read.

**Daemon record — `DAEMON_RECORD_VERSION` + 1.** The record's shape changed
(`title` may be an object), so it is bumped honestly instead of relying on
`parseSessionRecord`'s incidental check in another package. Composition with
2a: 2a plans 1 → 2 (`session-archive.md` "Record (on disk)"); the eval's order
puts 2a before 3, so **this task takes 2 → 3**; if 3 lands first, 3 takes 1 → 2
and 2a takes 3. `parseDaemonRecord` accepts every older version still read
(1, and 2 after 2a): their string title = `auto`. Every write is the current
version. `DaemonSessionState` gains `title: TitleState`; the persister encodes
it with `encodeTitle` instead of `sessionTitle` (`session-persister.ts:86-90`);
`restore` decodes it (`session-host.ts:193-213` → `RestoredSessionState.title`).
A rename / generated title calls `persist()` (a capture; the write is async,
`SessionPersister.schedule`, `:64-100`).

**Laptop store.** No version field exists; the string/object rule above is the
version lever (it is the only change an older build detects). The laptop
persists the daemon's title, never derives a new one over a stored one:

- `RemoteClient.snapshot` returns `{ messages, title? }` (first page's
  `title`, `remote-client.ts:1273-1305`); `RemoteSession.snapshot` likewise.
- `persistingController` (`local-runtime.ts:113-170`) keeps `lastTitle`
  (initialised from the resume record's `recordTitleState`) and updates it from
  each snapshot's `title` when present; **absent (an older daemon) → keeps
  `lastTitle`** (its own data). `persist(messages, lastTitle)` →
  `recordFromSnapshot(…, { title })` writes `encodeTitle`.
- **Idle title changes reach the laptop store:** `RemoteClient` routes
  `session_title` to per-session title listeners (like `background_exit`,
  `remote-client.ts:1144-1150`); `RemoteSession.onTitle(listener)`;
  `persistingController` subscribes and calls `flush()` (a snapshot read →
  save). Without this a rename right before quitting would be lost on pod /
  worker runtimes (they never persist daemon-side).
- **`--resume` picker / line** show `recordTitleText(record)`
  (`session-resume.ts:130-149`): the daemon's title as last persisted. The
  `open` seed sends `recordTitleState(record)` when it is not auto.
- **In-process fallback** (`main.ts:632-655`, `session-jobs.ts:96-130`): no
  daemon → no generation, no rename (`/rename` says "isn't available on this
  runtime"); its saves carry the seed record's title through unchanged (else
  resuming a renamed session there would overwrite the rename with the
  truncated message).

#### Client API + TUI `/rename`

- `RemoteClient.rename(sessionId, title)` → `Method.Rename`, same call path as
  `sessionList` (`remote-client.ts:329-336`). `MethodNotFound` → rejects with
  `"this daemon is too old to rename sessions — update tentacle"` (task 1's
  carry-over rule for `MethodNotFound`).
- `RemoteSession.rename(title)` (needs an opened id; before the first open →
  rejects "nothing to rename yet").
- `SessionController.rename?(title: string): Promise<string>` (`tui/src/App.tsx:69-85`),
  returns the stored text; `persistingController` forwards it.
- `commands.ts`: `/rename` in `SLASH_COMMANDS` ("rename this session (the title
  every device shows)"); pure `parseRename(raw)` → `{ title }` |
  `{ usage }` (no argument / only spaces → usage). `/rename` is NOT
  session-mutating (allowed mid-turn). A user skill named `rename` becomes
  shadowed (existing rule, `commands.ts:40-41` + `slashCatalog`).
- `App.tsx` `case "/rename"`: the controller lacks `rename` → "_Renaming isn't
  available on this runtime._"; else `pushNotice("_Renamed: <text>_")` with
  the daemon's returned text, or "_Rename failed: …_". No title is displayed
  live in the TUI today (nothing to update); task 6/7 add that view.

### Failure modes

| Case | Convergence |
|---|---|
| Model error / timeout (30 s) / empty or unusable text | stays `auto` (truncated first message); logged daemon-side; retried at the next turn end, ≤ 2 failures per incarnation. Never untitled, never a client guess. |
| A turn / send-now / compaction starts while generating | title job aborted first (never competes with the user); not a failure; retried at the next qualifying turn end. |
| Rename while generating (any order) | `applyGenerated` keeps a `user` state; the rename also aborts the job. User wins, forever: persisted in the daemon record + laptop store + re-seeded on recreate. |
| Rename during the 0-ms gap before the job starts | the macrotask re-checks `shouldGenerate` → `source: user` → no job. |
| Two clients rename concurrently | handlers are synchronous; last applied wins; each emits `session_title` in seq order, so every client converges on the last. |
| Session closed while generating | `close()` aborts; a late completion checks `closed` and emits/persists nothing. |
| Daemon restart (serve) | title restored from the record; `auto` sessions with an exchange are titled at their next turn end. |
| Pod / worker runtime, `--resume` | laptop seeds `open{title}` → no regeneration over a rename. |
| Pod daemon, laptop offline mid-generation | `ProxyModelProvider` fails / aborts → failure path; the pod never holds model creds. |
| Hostile pod: control chars / huge title | `line(MAX_SESSION_TITLE)` rejects the update/snapshot/list on the client (`text-line.ts:11`); it lies about `source` → display only. |
| Older client, newer daemon | `session_title` → `unsupported` once per session; snapshot/open fields dropped; it keeps writing string titles to its own store (its own data). |
| Newer client, older daemon | `session/rename` → `MethodNotFound` → clear message; snapshot without `title` → laptop keeps its stored title (never re-derives over a model/user one); `open.title` dropped (the old daemon has no titles at all). |
| Older build reads a new record (laptop or daemon) | object title → rejected loudly, left untouched; string title (auto) → read fully, nothing lost. Daemon: the version bump refuses every new record too. |
| Late attacher | in ring → replay; past a cut → snapshot `title` / list. |
| Rename with empty / whitespace / control-only text | `InvalidParams` (daemon); the TUI's `parseRename` already refuses the empty case. |
| Rename of a non-live id | `UnknownSession` (today) / record rewrite if archived (after 2a). |
| Compaction before any title | `auto` reads the summary (today's behaviour, `hosted-session.ts:1193-1195`); generation then titles from the summary + reply. |
| Rename right before quit (pod / worker) | `onTitle` → `flush()`; `dispose` already waits `allFlushed()` (bounded, `local-runtime.ts:279-286`). |

### Nuances decided during execution (all recorded, owner asked)

- **N1 — rename needs no prior `open`** (like `close`/`delete`/`list`): it
  is host-level. Reason: an archived session cannot be opened without
  reopening it, and the app renames from a list. Any authenticated client
  may rename any session (one token = one principal, as `close`).
- **N2 — archived rename: ALLOWED, in place, no reopen** (the plan's 2a
  branch). `entry.title` updates at once (`session/list` shows it), and
  `entry.renamed` is set; the record is rewritten in the background: the
  resident record if any, else read back with `persister.load` (which first
  waits for the id's latest write). Skipped if the entry is no longer
  archived when the read returns (reopened or deleted). A failed read →
  reported ("renamed in memory only"), the list and any reopen still keep
  the rename; a failed write → the 2a sweep retries it (the rewritten record
  stays resident until it lands).
- **N3 — reopen racing an archived rename**: `open` restores with
  `entry.renamed` over the record it read, so a reopen whose read started
  before the rewrite still shows the rename, and its own write (the live
  record, queued after) is the final one.
- **N4 — `settleWrite` now compares record identity** (a 2a seam touched):
  an older write settling after a rename rewrote the record must not drop
  the newer resident record nor clear its retry state. Callers pass the
  record they wrote (`archive`, `retryUnwritten`, `rewriteArchived`).
- **N5 — tombstoned id → `SessionDeleted`**; unknown → `UnknownSession`;
  nothing visible after sanitising → `InvalidParams` — for live and
  archived alike.
- **N6 — rename max length 80** (`TITLE_MAX`, the plan's constant, same as
  `sessionTitle`'s cut); generated titles too. Wire bound stays 256.
- **N7 — the title (seed/restored) never depends on persistence**: `build`
  passes `seed ?? restored.title` into `titling.seed`, so a `restore`
  without a persister still keeps the title.
- **N8 — timeout without `AbortSignal.any`**: the installed `@types/bun`
  lacks it in its types; one `AbortController` + a timer + a `timedOut` flag.
  An abort by the slot / rename / close is not a failure; a timeout is
  (`title generation failed: no answer within Nms`).
- **N9 — only a TURN end retries**: a compaction's end does not kick a
  title request (as planned: "at a turn's end"); the next turn end does.
- **N10 — `kickTitle` returns early when closed** (close → `finishTurn`
  would otherwise schedule a no-op timer).
- **N11 — `session/open{title}`** is honoured only on create; a live and an
  archived id ignore it (2a: the daemon's copy wins); the daemon re-sanitises
  it (`seedState`: `wireLine(…, 256)`, empty → `auto`).
- **N12 — the record's title in the archive index** is `recordTitleText`;
  `HostedSession.archive()` captures the title, so a closed session's
  archived record and list entry carry it (test).
- **N13 — a resync/read-back that reveals a chosen title the client missed
  notifies the title listeners** (past a cut the update is gone; only the
  snapshot says it) — so the laptop store converges on the daemon's title.
  An `auto` or absent title in a snapshot never overrides a known chosen
  one on the client side (the daemon reports `auto` only if it has no chosen
  title; the laptop's `persistingController` then stores `auto` — the
  daemon is the truth when it reports).
- **N14 — the in-process fallback** has no rename (controller lacks it:
  "_Renaming isn't available on this runtime._") and no generation; its
  saves carry the resumed record's title unchanged.
- **N15 — `connect` runtime** (`RemoteSession` as controller) gets `/rename`
  for free; it has no laptop store, so nothing to persist there.
- **N16 — the `/rename` notice** passes the daemon's text through
  `oneLine` (pod-supplied text) inside the TUI notice.

#### Attacks tried

1. **Hostile pod, laptop off: send `purpose:"title"`.** Refused with
   `InvalidRequest` on both transports, and the main model is never asked.
   Pinned by the gate test and confirmed red by mutation P. Holds.
2. **Hostile pod: omit `purpose`.** The call is served by the main model,
   exactly as before this task, so the pod gains nothing. Holds.
3. **Hostile pod: unknown `purpose` (`"summary"`, `"TITLE"`), or a `model`
   field in the request.** The inbound peer parse checks the method's schema
   (`peer.ts:338`), so a closed enum gives `InvalidParams` and the call is
   never served. `model` is stripped and pinned (`protocol/test/session-titles.test.ts:90-95`).
   I wrote an e2e scratch script for this (`r2-hostile.ts`), but running it
   needed an approval I did not have. This attack is therefore verified by
   reading plus the existing schema tests, not by an e2e run. Holds.
4. **Hostile pod, laptop on: a normal turn marked as a title.** It is served
   on `titleModel`. That grants nothing new (finding 2).
5. **Pod config says `autoTitle: true`, laptop says off.** `tunnelledAgent`
   overrides it with the laptop's flag, and even a lying daemon is refused at
   the laptop. Pinned ("laptop off + pod config on → no title call", N4). Holds.
