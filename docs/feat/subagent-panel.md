## Implementation

*— claude-opus-5-5, 2026-11-10*

### Load-bearing assumption

**The user's text reaches a running child through the SAME inbox the agent uses, and the parent's
`[user → sa-N]` note never wakes the agent.** Both halves are already true in code:
- `AgentJobs.message(agentId, text, from)` is synchronous, never throws, refuses with a reason
  (not running / being stopped / too long / closed / full), and formats the `"user"` sender
  (`core/src/agent-jobs.ts:393`; `docs/feat/agent-message.md` Design 1–2). The child drains at its
  boundaries (`runMessages`' `drainSteering`, polled at each iteration, `agent.ts:778,801`).
- The wake count is `Agent.pendingExitCount` (`agent/src/agent.ts:598-600`), read by
  `HostedSession.unflushedExits` (`daemon/src/hosted-session.ts:1283`). Putting the note in the same
  queue but EXCLUDING it from that count keeps "never wakes" (eval M2) while reusing the queue's
  carry-over on agent replacement (`retire`/`adoptExits`, `agent.ts:570-605`,
  `hosted-session.ts:1938`) and its flush point (`agent.ts:864`, after the user's message, never
  inside a round).

Test that proves it (T-A1/T-A2 below): a note pending → `pendingExitCount === 0`; the next turn's
history holds `[user → sa-1] …` right after the user message; `retire()` → `adoptExits()` keeps it.

### Preconditions

- **TUI over RPC, one path (§7).** The in-process worker, pod `run`/`attach` and `connect` all go
  through `RemoteClient` ↔ `Connection`; the new methods are added to that stack only
  (`daemon/src/connection.ts:268-280` is where `ResolvePermission`/`Rename` dispatch).
- **Peer not serialized (§7).** `session/subagent_message` and `session/agent_kill` are short,
  synchronous handlers; they run concurrently with a long `session/prompt` (`transport/peer.ts`,
  `void handleRequest`). Nothing here awaits a turn.
- **Protocol forward-compat (§7, v10).** A new method → an older daemon answers `MethodNotFound`; a
  new `display` update → an older client shows `unsupported` once (`protocol/src/updates.ts:323,339`
  class table). Hence **no `PROTOCOL_VERSION` bump** (now 21, `protocol/src/version.ts:17`).
- **Display updates reach every attached client while idle**: `publishSubagents` → `emit` +
  `recordCut(null)` when idle (`hosted-session.ts:1231-1245`). The new update uses the same path.
- **A pod is not trusted (§7).** Rows are bounded/sanitized in the client
  (`client/src/subagents.ts:1-7`); the new update's text is bounded the same way. Neither method
  has a laptop effect, so no laptop gate is involved; a child's permission ask still goes through the
  single broker (unchanged).
- **The background-child ask names its `sa-N`** in the TUI: `PermissionAgent.id`
  (`tui/src/permission-ui.ts:33-38`), exposed as `permission.pendingAgent` (`:166`). Rows from the
  daemon always say `state: "running"` (`core/src/agent-jobs.ts:227`), so "waiting on you" is
  derived from `pendingAgent.id`, not from the row.
- **Key priority today** (`App.tsx` `useInput`, `:2489`): quit confirm (`:2506`) → permission prompt
  (`:2536`) → paste → open panel (`:2646-2730`) → Esc stops a turn (`:2731`) → Ctrl+O (`:2736`) →
  palette (`:2743-2772`) → mouse → line editing via the pure `resolveLineInput`
  (`input-actions.ts:50-66`: DOWN = `moveVertical` while a line is below the cursor, else
  `history +1`) → `historyStep` (`App.tsx:2900-2918`; `history.ts:38-60`: on the draft slot DOWN is a
  no-op).
- **Selection grammar** to copy: accent + bold on the selected row, the rest dimmed
  (`components/ListPanel.tsx:25-27`, `CommandPalette.tsx:30`).
- **Exit notice already exists**: `backgroundExitNotice(..., agent)` →
  `sa-1 finished · 19 tool uses · … — report sent to the agent` (`tui/src/state.ts:151-169`).
- **The App re-renders on the list only when its ids change** (`App.tsx:646-656`, `sameIds`, LOW-4);
  the full rows stay in `subagentsRef`.

### Design

#### 1. Daemon: two methods, one display update, one parent note

- **`session/subagent_message {sessionId, agentId, text}`** → `{ ok: true } | { ok: false, reason }`.
  `text`: `min(1).max(AGENT_MESSAGE_MAX_CHARS)` (8000, task 8). `HostedSession.messageSubagent(id,
  text)` (sync): `agentRuntime?.message(id, text, "user")` (absent runtime → `ok: false`, "background
  sub-agents are not available in this mode"). On `ok`:
  1. `session.noteUserToSubagent(id, text)` — the parent's pending note (below);
  2. `emit({ type: "subagent_message", agentId: id, text })` (+ `recordCut(null)` when idle, as
     `publishSubagents`) — every attached TUI shows it, the sender included (ONE render path, no
     local echo; two TUIs stay consistent).
  On refusal: the reason, nothing noted, nothing emitted.
- **`session/agent_kill {sessionId, agentId}`** → `{ killed: boolean }` = `agentRuntime?.kill(id) ??
  false` (`agent-jobs.ts:276`). The exit, its note and the list update follow from the existing path.
- **The parent note.** `PendingExit` (`agent.ts:228`) gains a third member
  `{ kind: "user_note"; agentId; text }`. `Agent.noteUserToSubagent` pushes it; `pendingExitCount`
  counts only the non-note members; `flushBackgroundExits` writes it as a user-role message:
  ```
  [user → sa-1] skip the tests folder
  (the user wrote this directly to background sub-agent sa-1; it was delivered to it. For your information: no reply is expected.)
  ```
  with `note: { kind: NOTE_KIND.userToSubagent ("user_to_subagent"), id: "sa-1" }`
  (`core/src/model.ts:83-92`; `note.kind` is a free string, no schema change), so `--resume` renders
  it as a notice, not a typed row (`tui/src/resume.ts:17-48`). It emits NO event (the TUI already
  showed the live notice). It is persisted as an ordinary `message` entry (no new log type, eval
  table :188). Exact second line: owner question P7. `Session` (`agent/src/session.ts`) passes
  `noteUserToSubagent` through.

#### 2. Client

- `RemoteClient.messageSubagent(sessionId, agentId, text)` / `killSubagent(sessionId, agentId)`
  through `this.call(...)` (pattern: `Rename`, `remote-client.ts:717`). `MethodNotFound` → a typed
  refusal `"this daemon cannot message sub-agents (older version)"` (never thrown at the TUI).
- The `subagent_message` update: routed beside `subagents` (`remote-client.ts:2296`), bounded in
  `subagents.ts` (`boundSubagentMessage`: control chars except `\n` stripped as `progressText` does,
  ≤ 8000 chars, `agentId` ≤ 64), to `onSessionSubagentMessage` listeners; `mapping.ts:280-284`
  returns no `AgentEvent` for it (non-turn, like `subagents`).
- `RemoteSession`: `messageSubagent(agentId, text)`, `killSubagent(agentId)`,
  `onSubagentMessage(listener)` (pattern: `onSubagents`, `remote-session.ts:458-470`).

#### 3. TUI pure modules (all logic here, unit-tested; components only paint)

- **`background-list.ts`** (new) — the view-model of the dock under the footbar.
  `backgroundListView({ rows, jobs: [], askingId, focus, width, now }) → ListView`:
  - `header`: `{ label: "background", count, right: hint }`; the hint by focus:
    unfocused `↓ select · ctrl+t` (`↓ · ctrl+t` under 70 cols), list `enter open · x stop · esc
    back`, armed `y stop · any other key cancels`, overflow prefix `↑k ↓m`.
  - `rows`: at most **`LIST_MAX_ROWS = 5`** (mockup 05), a window that follows the selection; order =
    launch order, sub-agents first then shell jobs (stable: nothing jumps).
  - Per row: `{ id, glyph: "running" | "asking" | "job", typeCol?, description, meta, selected,
    armed }`. `meta`: `19 tools · 12.4k · 1m12s` (≥ 90 cols), tokens dropped < 90, type column
    dropped < 60, `⚠ needs your permission` when `id === askingId`; description cut by CELLS
    (`cells.ts` `truncateCells`); durations via `format.ts` `formatDuration` (`:46`).
  - `drawerView(row | frozen, sent, outcome, width)` → `{ head, meta, hidden, tail, sent }`:
    `… +k earlier` = `toolUses − tail.length` when positive; `tail` = the row's labels (≤ 8);
    `sent` = the last 3 texts sent to it (one line each, cut by cells); `outcome` once it ended.
  - `inputTitle(focus)`: `null` (the model rule as today) | `{ target: "sa-1", sub: "explore" |
    "finished" }` — `status-line.ts` gains `targetBorder(title, width)` beside `modelBorder`
    (`:24-34`).
  - `listVisible(rows, jobs)`: true iff ≥ 1 row. The StatusBar's ` · N sub-agents` suffix is
    suppressed while the list is visible (the list says it).
- **`background-focus.ts`** (new) — the focus state machine and key routing.
  ```ts
  type DockFocus =
    | { kind: "input" }
    | { kind: "list"; selected: string; armed: boolean }
    | { kind: "open"; id: string; ended: Outcome | null; frozen: Row | null };
  interface DockState { focus: DockFocus; drafts: Readonly<Record<string, string>>; sent: Readonly<Record<string, readonly string[]>> }
  downEntersList(ctx: { action: LineAction; onDraftSlot: boolean; paletteOpen: boolean; visible: boolean; focus: DockFocus }): boolean
  dockKey(state, char, key, ctx: { ids: readonly string[]; openable: (id) => boolean }): { state; effect: DockEffect }
  // DockEffect: none | pass (not mine) | stop{id} | open{id, draftOut, draftIn} | close{draftOut, draftIn} | notice{text}
  reconcile(state, ids, ended: { id; outcome }[]): DockState   // rows changed / a child ended
  sendTarget(state, text): { kind: "main" } | { kind: "agent"; id } | { kind: "refused"; text }
  ```
  The App's handler gains ONE dispatch before the Esc-stops-turn branch (`App.tsx:2731`) and ONE
  check before `historyStep`, and executes effects; it decides nothing.

#### 4. The keyboard model (mockup 02 has the table)

Focus ring: **input ⇄ list**, and **open** (the input re-targeted to one child).

| Focus | Key | Does |
|---|---|---|
| input / open | ↓ | In order: (1) palette open → palette (unchanged); (2) a line below the cursor → move down (unchanged); (3) inside a history walk (`histIndex < items.length`) → history toward the draft (unchanged); (4) on the draft slot, last line, list visible, focus `input` → **enter the list on its first row** (P8); (5) else nothing. In `open` (drawer shown, list hidden) step 4 does not apply. |
| input / open | ↑ | unchanged (line up, then history). |
| any | Ctrl+T, `/agents` | toggle: input/open → list (from anywhere: multi-line draft, mid-history); list → back. Empty list → notice "Nothing is running in the background." |
| input | Esc | unchanged (stops a running turn, `App.tsx:2731`). |
| any | PgUp/PgDn | scroll the transcript (unchanged). |
| list | ↑ / ↓ | move; ↑ on the first row → back to the input (cursor and draft untouched); ↓ on the last row stays (no wrap). |
| list | Enter | open the selected sub-agent: stash the main draft, restore that child's draft. A shell row: P6. |
| list | x | arm "stop sa-N? y/N" on that row; `y` → `session/agent_kill`; any other key disarms and is swallowed (P4). |
| list | Esc / Ctrl+T | back to the input. **Never stops the turn.** |
| list | printable | P3 (recommended: ignored). |
| open | Enter | non-empty text not starting with `/` → `session/subagent_message` (never the main agent, never steering, never queued); text starting with `/` → the command path as today. Ended target → refused with a notice, draft kept (never re-routed). Over 8000 chars → refused before sending. |
| open | Esc | close: stash the child's draft, restore the main draft. Does NOT stop the turn (a second Esc does). |
| any | Ctrl+C, quit confirm, permission prompt | unchanged and FIRST: both own every key while shown (`App.tsx:2506,2536`); the dock state is untouched underneath. |

Mouse: out of scope (wheel unchanged; a click on a row does nothing): a follow-up.

### Failure modes

| Case | How state converges |
|---|---|
| Selected row's child ends | `reconcile`: selection kept by id; when it leaves, the row that took its place (else the one above); list empty → focus `input`, draft untouched. |
| Open child ends | Drawer frozen on its last row + outcome (from the live `background_exit` already received); input keeps `→ sa-1 · finished`; Enter refused with a notice, draft kept; Esc closes. Never a silent re-target to the main agent. |
| Child ends between Enter and the RPC | Daemon refuses (`not a running background sub-agent …`); notice with the reason; the text is put back into that target's draft if it is still empty, else quoted in the notice. Same for `full` / `closed` / `being stopped`. |
| Older daemon (no method) | `MethodNotFound` → typed refusal → notice "this daemon cannot message sub-agents (older version)"; Enter on a row still opens (read-only drawer). |
| Older client, newer daemon | `subagent_message` shown `unsupported` once (display class); the methods are never called. |
| Many items | 5-row window, `↑k ↓m` in the rule; client keeps ≤ 32 (`MAX_SUBAGENT_ROWS`). |
| Resize | Views recomputed from `columns` each render; selection by id, never index; narrow tiers at 90/60 cols; every row one line (cells-cut). |
| Two TUIs on one session | Focus/drafts are per TUI; the list and the `subagent_message` notice are the session's (broadcast to all); both may open sa-1; the inbox cap (8) is shared and refusals say so. |
| A child asks a permission while list/open | The prompt owns keys first (`App.tsx:2536`) and replaces the input as today; the dock state is untouched; the row shows ⚠ for `pendingAgent.id`. After the answer the same focus comes back. Only the ask ON SCREEN is marked (queued asks are not visible to the TUI: noted debt). |
| `/clear` | Background work stays (`docs/feat/clear-keeps-jobs.md`); a pending `[user → sa-N]` note stays in the agent's queue (same object, not reset) and lands in the cleared chat at its next turn, like the child's report. The dock keeps its focus; an open drawer stays. |
| Session switch (`/sessions`, resume) | Dock state reset to `input`, `sent` cleared (it is per session). |
| Quit confirm | Owns every key while shown (`App.tsx:2506`); the count it names is unchanged (`backgroundNames`). Ctrl+C in list/open behaves as in the input. |
| Agent replaced (settings sync) | The note rides `retire()`→`adoptExits()` (`hosted-session.ts:1938`). |
| Daemon restart (`serve`) | A pending note is memory-only and is lost with the child (the child's own "lost" note covers it). Accepted: same as pending exits. |
| Pod daemon sends a hostile `subagent_message` | Bounded in the client; display only; it can at most print a notice. No laptop effect. |
| Turn running while writing to a child | Enter in `open` never queues/steers the main turn; the note waits for the parent's NEXT turn (never mid-round, `agent.ts:860-866`). |
| Note shown live vs on resume | Live: at send time. Resume: where it was flushed (after the next user message). Same text; position differs by design (the durable record is the parent's note). |
| Text starting with `/` meant for the child | Runs as a command (debt: no escape; P-free, noted). |
